# 01 — Архитектура

Полное описание — `docs/specs/2026-09-26-pylesos-design.md`, разделы 1–2.

## Жёсткие правила
- Одна локальная программа (П10): Go-бинарник со встроенным React-фронтом, окно — Chromium `--app`, сервер на `127.0.0.1`.
- **Три независимых шага (П16): сбор → разбор → таблица.** Сырые данные не смешиваются с результатами разбора,
  разбор не зависит от шаблона таблицы. Каждый шаг продолжается с места остановки.
- Всё длительное — **задание** (`internal/jobs`): курсор в базе, статусы, пауза/продолжение, продолжение после перезапуска.
  Новый вид работы = новый `Worker`, а не своя горутина со своим состоянием.
- Внешнее (Telegram, OLX/браузер, Ollama, ОС) — только за интерфейсами.
- Код из doc-agent копируется (П5) и приводится к этим правилам; зависимости от `~/doc-agent` нет.
- Под внешние системы (taxi-saas-platform и др.) не подгоняем (П4).

## Структура

```
cmd/pylesos/            — запуск и сборка зависимостей (DI)
internal/
  api/                  — HTTP: guard, экраны, действия, SSE
  screens/              — сборка экранов для тонкого фронта (тексты, статусы, кнопки)
  texts/                — все тексты интерфейса (П22)
  events/               — оповещения окон (SSE)
  jobs/{domain,repository,service}      — задания и их исполнитель (Runner)
  settings/{domain,repository,service}  — настройки
  store/                — открытие SQLite, миграции; storetest/ — база для тестов
  window/, instance/    — окно программы, повторный запуск
  paths/, logger/
  (M2+) telegram/, sites/, analyze/, recognize/, tables/, export/
web/                    — React (Vite), web/embed.go встраивает dist
```

## Модули
Модуль = `internal/<модуль>/{domain,repository,service}`. Модуль зависит от других только через узкие интерфейсы,
объявленные у себя (порты), а не импортом чужого `service` целиком.
