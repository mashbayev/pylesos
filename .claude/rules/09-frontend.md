## 🛑 THIN CLIENT (П3) — ЖЁСТКОЕ ПРАВИЛО

**Вся логика — только в Go. Браузер — только рендерит.**

1. **Никаких вычислений в браузере** — статусы, счётчики, суммы, форматирование дат/чисел делает Go
2. **Один экран — один запрос** (`GET /api/screens/<экран>`), Go собирает всё и отдаёт плоский JSON
3. **Фильтрация, сортировка, пагинация — серверные**
4. **React Query без трансформаций** — данные рендерятся «как есть», никаких `useEffect` с преобразованиями
5. **Тексты интерфейса приходят с бэкенда** (П22). Исключения — только то, что нельзя получить от бэкенда:
   «нет связи с программой» и текст ErrorBoundary

Запрещено:
- `filter()` / `reduce()` для бизнес-агрегатов (только для рендера)
- Проверки ввода, дублей, бизнес-правил — Go возвращает готовые ошибки по полям и флаги
- Менять статус объекта логикой фронта
- **Нужна новая «логика» во фронте → сначала Go-endpoint с нужным полем в JSON**

## Данные API
- Пустые списки бэкенд отдаёт как `[]`
- Действие (`POST`) возвращает обновлённый экран целиком → `queryClient.setQueryData(['screen', имя], ответ)`
- Изменения на бэкенде приходят событием SSE (`/api/events`) → `invalidateQueries({ queryKey: ['screen'] })`

### `queryKey` — одна форма данных на ключ
Ключи экранов — `['screen', '<имя>']`, `queryFn` для ключа всегда один (`useScreen`). Перед новым ключом — grep, что он не занят.
