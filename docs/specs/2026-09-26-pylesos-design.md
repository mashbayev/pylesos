# Пылесос — спецификация

Все разделы утверждены пользователем 2026-09-26. Основа — `.claude/rules/00-decisions.md` (П1–П23) и правила кода в `.claude/rules/`;
при противоречии правила старше спецификации.

## 1. Архитектура ✅ (2026-09-26)

Одна локальная программа (П10): запускается, открывает своё окно (механизм окна — из doc-agent),
HTTP-сервер слушает только `127.0.0.1`.

**Где лежат данные** (уточнение П10): база, профиль браузера OLX и временные файлы — в папке данных пользователя
(`os.UserConfigDir()/Пылесос`); выгрузки Excel — в `Документы/Пылесос/` (папку можно сменить в настройках).

```
                    React (тонкий, только рендер)
                              │  HTTP JSON + поток событий (SSE)
┌─────────────────────────────▼──────────────────────────────┐
│ api        — хэндлеры: экраны, действия, прогресс           │
├────────────────────────────────────────────────────────────┤
│ Сервисы:                                                   │
│  collect   — задания сбора: запуск, пауза, продолжение      │
│  telegram  — account (gotd: история, догрузка пропусков)    │
│              bot (Bot API: новые сообщения)                 │
│  sites     — интерфейс площадки; olx (chromedp + JSON API)  │
│  analyze   — Telegram: кто упомянут, склейка людей,         │
│              ответы → комментарии                           │
│  recognize — документы → текст/поля (копия doc-agent)       │
│  tables    — конструктор шаблонов (копия + новые режимы)    │
│  export    — Excel (копия doc-agent)                        │
├────────────────────────────────────────────────────────────┤
│ repository — SQLite (sqlx), миграции                        │
└────────────────────────────────────────────────────────────┘
    внешнее: Telegram (MTProto, Bot API) · Chromium · Ollama
```

**Три независимых шага:**
1. **Сбор** — сырые сообщения и объявления в базу как есть.
2. **Разбор** — распознавание документов, поиск людей, склейка упоминаний; результат хранится.
3. **Таблица** — шаблон конструктора применяется к разобранным данным → Excel.

Каждый шаг прерывается и продолжается с места остановки; повторный запуск обрабатывает только новое.

## 2. Модель данных ✅ (2026-09-26)

SQLite, схема только миграциями (правила кода). Значения ячеек кэшируются **по каждой колонке отдельно**:
смена порядка/названий колонок и служебные поля (автор, дата, ссылка) — мгновенно; новая смысловая колонка
требует одного прохода модели только по ней.

### Слой «Сбор» (сырые данные)

| Таблица | Что хранит |
|---|---|
| `sources` | источник: Telegram-группа (id, название) или площадка (`olx`) |
| `jobs` | задание (сбор или разбор): тип (история TG / догрузка / поиск на сайте), параметры (запрос, фильтры, режим телефонов все/отмеченные), статус (в очереди / идёт / пауза / ждёт пользователя / готово / ошибка), курсор продолжения, счётчики |
| `tg_messages` | сообщение: группа + id (уникально — аккаунт и бот не дублируют), дата, автор, текст/подпись, ответ на, ветка, пересылка, правка/удаление, кто принёс (аккаунт/бот), сырой JSON |
| `tg_media` | вложение: тип (фото/PDF/документ), ссылка для повторного скачивания, статус (ждёт / скачано / распознано / файл удалён по П12), распознанный текст, модель |
| `offers` | объявление: площадка + внешний id (уникально), ссылка, заголовок, описание, цена, город, продавец, параметры категории, `has_phone`, телефон и его источник (текст / кнопка), статус телефона, отметка «открыть телефон», первое/последнее появление, сырой JSON |
| `offer_hits` | какое задание нашло какое объявление (одно объявление — в разных запросах) |

### Слой «Разбор» (Telegram)

| Таблица | Что хранит |
|---|---|
| `persons` | человек: каноническое ФИО, ИИН (уникален, если известен), № документа, дата рождения |
| `mentions` | упоминание: человек, сообщение, роль (запись / запрос / комментарий), имя как написано, способ привязки (ИИН / точное имя / похожее имя / цепочка ответов / вручную), уверенность |
| `merge_candidates` | пары «возможно, один человек» и решение пользователя (ждёт / склеены / отклонены); отклонённая пара больше не предлагается |

### Слой «Таблица»

| Таблица | Что хранит |
|---|---|
| `templates` | шаблон конструктора (модель doc-agent + новые режимы строк + источник значения у колонки) |
| `cell_cache` | сущность (человек/сообщение/объявление) + подпись колонки (имя, тип, подсказка) + хэш входных текстов → значение, уверенность, замечания проверки |
| `exports` | выгрузка: шаблон, файл, число строк, дата |

### Прочее

- `secrets` — сессия Telegram, токен бота; зашифрованы AES-256-GCM (правила кода), ключ — в файле в папке данных
  с правами только для владельца. Остальная база не шифруется (П12). Cookies OLX — в профиле Chromium, не в базе.
- Люди общие для всех групп (П18).

## 3. Сбор ✅ (2026-09-26)

### Telegram — аккаунт (история, догрузка)
1. Разовая настройка: пользователь получает `api_id`/`api_hash` на my.telegram.org и вводит в настройках; затем
   номер, код, облачный пароль — сам, в окне программы. Сессия хранится зашифрованной.
2. История: выбор группы из списка аккаунта → выгрузка страницами, курсор сохраняется после каждой страницы.
   FLOOD_WAIT → ждать указанное время, показывать в статусе.
3. Медиа на сборе не скачиваются — только ссылка; скачивание, распознавание и удаление — на разборе (П12).
4. При каждом запуске — догрузка всего после последнего сохранённого сообщения.

### Telegram — бот (новые сообщения)
- Токен от @BotFather вводит пользователь; бот добавлен в группу админом.
- Long polling (без вебхука — программа локальная); правки сообщений тоже принимаются.
- Номера сообщений бота и аккаунта в супергруппах совпадают → ключ «группа + номер» исключает дубли.
- Удаления бот не видит — их замечает следующая догрузка аккаунтом.
- Правки старых сообщений ловит только бот, пока программа запущена; догрузка аккаунтом берёт только новые сообщения.

### OLX
1. Отдельный Chromium со своим профилем в папке данных. Телефоны нужны, а входа нет → статус
   «ждёт пользователя: войдите в OLX», окно на передний план.
2. Поиск: запрос + фильтры (город, категория, цена; варианты отдаёт бэкенд). Страницы по 50, пауза 1–3 с,
   курсор — смещение в выдаче.
3. Телефон из текста: казахстанские номера в заголовке и описании, проверка валидатором из doc-agent.
4. Телефон по кнопке — для всех или отмеченных (режим задания); пауза между открытиями настраивается,
   по умолчанию ~30 с.
5. Капча/блокировка → пауза, «ждёт пользователя» (П11). Дневной лимит показов исчерпан → пауза до следующего дня
   или до команды «продолжить».

### Общее
- Состояние и курсор — в базе; после закрытия программы или сбоя задание продолжается с места остановки.
- Одно задание на источник одновременно; Telegram и OLX — параллельно.
- Прогресс — потоком событий, фронт только показывает готовые строки статуса.

## 4. Разбор Telegram ✅ (2026-09-26)

Идёт по неразобранным сообщениям строго по одному (одна видеокарта, одна Ollama). У сообщения — статус разбора;
повторный запуск берёт только новые и изменённые (правка → упоминания сообщения пересчитываются).

### Шаг 1. Документы
Скачать → привести к картинкам (фото, PDF — код doc-agent) → распознать → удалить файл (П12).
Из doc-agent: транскрипция, поиск карточки документа на скрине, подробное чтение мелкого текста, исправление гомоглифов.
Извлекаются только опознавательные поля: ФИО, ИИН (проверка контрольной цифры), № документа, дата рождения.
Полный распознанный текст сохраняется.

### Шаг 2. Кто упомянут
Вход модели: текст сообщения + опознавательные поля его документов + текст сообщения, на которое это ответ.
Ответ строго по JSON-схеме: список людей {имя как написано, ИИН если есть, роль: запись / запрос / комментарий}.
Причины, суммы и прочее здесь **не извлекаются** — это колонки шаблона (раздел «Таблица»); разбор не зависит от шаблона.

### Шаг 3. Привязка к человеку (П17)
Первое совпадение побеждает:
1. ИИН с верной контрольной цифрой → человек с этим ИИН (нет — создать).
2. Точное совпадение нормализованного ФИО → только если такой человек **один**; несколько — «не привязано».
3. Имени в тексте нет, есть документ → имя и ИИН из документа.
4. Имени нет вообще → цепочка ответов: реплика на сообщение о человеке = его комментарий.
5. Ничего не подошло → список «не привязано», пользователь привязывает вручную.

Подтверждённая склейка и ручная привязка в первой версии **не отменяются** (кнопки «разделить» нет).

Имя в подписи расходится с документом → верим документу, пометка «ФИО в подписи отличается от документа»
(жёлтая ячейка в Excel).

### Шаг 4. Нормализация ФИО и кандидаты на склейку
- Нормализация: нижний регистр, ё→е, казахские буквы → русские (ә→а, қ→к, ң→н, ө→о, ұ/ү→у, і→и, ғ→г, һ→х),
  латиница → кириллица, порядок слов не важен.
- Отображаемое имя: из документа (с казахскими буквами), иначе самое частое написание.
- Новый человек сравнивается с остальными (похожесть имён; совпадение фамилии и имени при отчестве у одного из двух)
  → пары в `merge_candidates`.

### Служебные значения человека (Go, без модели)
Число записей, группы, кто добавлял, первая/последняя дата, ссылки на сообщения, число комментариев.

### Скорость
Документы ~6 с/страница (gemma4:e4b, 6 ГБ видеопамяти), короткие тексты ~2–3 с.

## 5. Конструктор и таблица ✅ (2026-09-26)

### Шаблон (модель doc-agent, изменённая)
- «Строка таблицы =»: **человек** (люди Telegram после склейки) / **сообщение** (каждое сообщение Telegram) /
  **объявление** (объявления площадок). Режимы doc-agent document/page/table_rows не переносятся.
- Колонка: название, тип, подсказка, обязательность, варианты (как в doc-agent) + **источник**:
  - «Модель» — ИИ извлекает по подсказке из текстов строки (человек: все записи, тексты документов, комментарии —
    с датами и авторами; объявление: заголовок, описание, параметры). Как сводить несколько записей — решает подсказка.
  - «Поле» — готовое значение из Go без модели (человек: ФИО, ИИН, № документа, число записей, группы, авторы,
    даты, ссылки, комментарии; объявление: ссылка, цена, город, продавец, телефон и его источник).
    сообщение: дата, автор, группа, текст, ссылка; список полей по режиму отдаёт бэкенд.
- Из doc-agent: предложение колонок моделью, проба шаблона на одной строке, импорт/экспорт шаблона файлом.

### Зоны на образце (П21)
Переносятся из doc-agent сразу. В Пылесосе зоны принадлежат не шаблону таблицы, а **формам документов**
(удостоверение — лицевая/оборотная, права и т.п.), которые использует разбор (раздел 4, шаг 1):
пользователь один раз размечает образец, где стоят ФИО, ИИН, № документа, дата рождения.
Форма опознаётся по отпечатку образца; для скринов переписки — поиск карточки документа (Locator) из doc-agent.
Документ неизвестной формы читается моделью целиком.

### Построение таблицы
1. Пользователь выбирает шаблон, источники (группы / задания поиска), фильтры (период, П20). Фильтрует бэкенд.
2. Для каждой строки — `cell_cache`; недостающие колонки «Модель» извлекаются **одним запросом на строку**
   по JSON-схеме. Прогресс — потоком событий.
3. Ключ кэша включает хэш входных текстов: новая запись о человеке → пересчёт только его ячеек.
4. Проверка значений по типу колонки валидаторами doc-agent (ИИН, даты, суммы, телефоны).

### Excel (экспорт doc-agent)
- Строка на сущность, колонки в порядке шаблона, настоящие типы ячеек.
- Сомнительные ячейки — жёлтые, с примечанием.
- Ссылки на сообщения Telegram и объявления — кликабельные.
- Лист «Параметры»: шаблон, источники, фильтры, дата выгрузки.
- Файл в `Документы/Пылесос/`; «Открыть файл» / «Открыть папку» — через бэкенд.

## 6. Экраны ✅ (2026-09-26)

Каждый экран — один `GET` (бэкенд отдаёт готовые тексты, статусы, доступные кнопки, отформатированные значения);
действия — `POST`; прогресс — один поток событий (SSE). Фронт ничего не считает (П3). Язык — русский (П22).

| Экран | Содержимое |
|---|---|
| Источники (главная) | Telegram-группы: последняя догрузка, бот вкл/выкл, сколько не разобрано. Поиски OLX: запрос, число объявлений, телефоны открыто/осталось. «Собрать», «Разобрать», «Выгрузить». Плашка «ждёт пользователя» |
| Задания | все сборы и разборы с прогрессом; «Пауза», «Продолжить»; причина остановки |
| Люди | поиск по ФИО/ИИН (на сервере); карточка: записи, комментарии, поля документов, ссылки; вкладки «Возможно, один человек» (подтвердить/отклонить) и «Не привязано» (привязать вручную) |
| Поиск OLX | новый поиск: запрос, фильтры, режим телефонов; таблица объявлений с отметками «открыть телефон» (хранятся на бэкенде); «Открыть телефоны отмеченных» |
| Шаблоны | конструктор как в doc-agent: колонки, типы, источник «Модель/Поле», подсказки, предложение колонок, проба на строке, импорт/экспорт |
| Формы документов | образцы документов и разметка зон мышью (П21) |
| Выгрузка | шаблон, источники, фильтры → построение с прогрессом → «Открыть файл» / «Открыть папку»; история выгрузок |
| Настройки | Telegram (`api_id`, вход), бот (токен, статус), OLX (открыть браузер, вошёл ли), Ollama (модель есть/нет), папка выгрузок, пауза между телефонами |

## 7. Ошибки и тесты ✅ (2026-09-26)

### Ошибки
Сбой одной части не останавливает остальные; каждое сообщение об ошибке — готовая русская фраза от бэкенда.

| Ситуация | Поведение |
|---|---|
| Ollama не запущена / нет модели | задания разбора — «ждёт: запустите Ollama»; сбор продолжается |
| Пропала сеть | повторы с нарастающей паузой, продолжение с курсора |
| Сессия Telegram отозвана | «войдите в Telegram заново», сбор истории ждёт |
| Неверный токен бота | статус бота в настройках и на главной |
| OLX изменил формат ответа | задание останавливается с причиной «OLX изменил формат ответа»; сырой ответ сохраняется |
| Нет Chrome/Chromium | сообщение, где взять (как в doc-agent) |
| Модель вернула не тот JSON | один повтор → сообщение «не разобрано: ошибка модели», разбор идёт дальше; такие видны в «Заданиях», можно повторить |
| Программа закрыта посреди задания | при запуске — продолжение с сохранённого курсора |

### Тесты
Пишутся вместе с кодом; `go test` и `go vet` — всегда.
- Telegram, OLX, Ollama, браузер — за интерфейсами; в тестах — подставки, живые сервисы не участвуют.
- Набор вымышленных сообщений (П8) на все форматы из `docs/research/telegram-chs-astana.md`.
- Нормализация ФИО и склейка — табличные тесты; отдельно — что два разных человека **не** склеиваются (П17).
- OLX — на сохранённых вымышленных ответах API.
- Excel — выгрузить → прочитать → сверить типы и жёлтые ячейки; тесты doc-agent копируются вместе с кодом.
- Прогон на реальной модели (как `bench` doc-agent) — на вымышленном наборе, только по просьбе пользователя.
- Фронт — только строгая проверка типов TypeScript и сборка (логики в нём нет).
