# M4 — Разбор Telegram (MVP). Короткий план

> Режим П27: короткий план, код пишется по TDD при выполнении; одно ревью в конце.

**Goal:** Кнопка «Разобрать» у группы: документы из сообщений распознаются (ФИО, ИИН, № документа, дата рождения — по формам документов или моделью целиком; файл не сохраняется, П12), в каждом сообщении модель находит упомянутых людей и роль (запись / запрос / комментарий), упоминания привязываются к людям (П17), похожие имена попадают в «Возможно, один человек». Экран «Люди»: поиск, карточка, подтверждение склейки, ручная привязка.

**Spec:** раздел 4 целиком; П7, П12, П17, П18, П20, П26, П27. Правила: `03-telegram.md`, `05-recognition-llm.md`.

## Решения
- Анализ — задание `tg_analyze` на источник (M1): фаза «документы» → фаза «сообщения», курсор в задании, повтор разбирает только новое.
- Модель — `ollama.Preferred(VisionModels)`; Ollama не отвечает или модели нет → задание «ждёт вас» (спецификация, раздел 7).
- Файл вложения скачивается аккаунтом по номеру сообщения (свежая file_reference), держится только в памяти (П12).
- Опознавательные поля документа: `recognize.Extractor.Extract` с шаблоном из четырёх полей (`docforms/domain.FieldColumn`) и формами (`AsTablesForm`) — зоны, если форма узнана, иначе модель по всей странице; текст страницы — `Transcriber.Page`.
- Упоминания в сообщении: один запрос к модели по JSON-схеме `{"mentions":[{"name","iin","role"}]}`; вход — текст сообщения, поля его документов, текст сообщения, на которое ответ.
- Привязка (раздел 4, шаг 3): ИИН с верной контрольной цифрой → человек по ИИН (создать); точное нормализованное ФИО и такой человек один → он; нет такого → новый человек; несколько → «не привязано»; имени нет, есть документ → поля документа; ни имени, ни документа, ответ на сообщение о человеке → комментарий к нему.
- Правка сообщения (новая `edit_date`) сбрасывает отметку «разобрано»; повторный разбор заменяет упоминания сообщения.
- Кандидаты склейки: одинаковые фамилия и имя при разном числе слов (отчество), либо одно слово отличается одной буквой (длина ≥ 5); отклонённая пара больше не предлагается.

## Задачи
1. Миграция 0005: `persons`, `mentions`, `merge_candidates`; `tg_messages.analyzed/analyze_error`; `tg_media.fields`; upsert сообщения сбрасывает `analyzed` при новой правке.
2. `internal/people/names`: нормализация ФИО (регистр, ё, казахские → русские, латиница → кириллица, порядок слов) и похожесть — табличные тесты, включая «два разных человека не похожи».
3. `internal/people/{domain,repository}`: люди, упоминания, кандидаты, склейка (перенос упоминаний, заполнение пустых полей, удаление второго).
4. Шлюз: `Media(ctx, peer, msgID) ([]domain.File, error)` — скачивание фото (наибольший размер) и документов через `downloader`.
5. `internal/analyze`: сервис документов, сервис упоминаний (запрос к модели и разбор ответа), привязка; воркер `tg_analyze` — тесты на подставках модели и шлюза и на настоящей базе.
6. Экран «Люди» + API + React; кнопка «Разобрать» на главной.
7. Сборка, проверки правил, ревью.
